# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

This is **py4e** (Python for Everybody, py4e.com) — the course website, not the Python
lessons themselves. It is a PHP application built as an app **on top of the Tsugi LMS
framework**. The Tsugi framework lives in a `tsugi/` subfolder that is **gitignored and
not part of this repo** — it must be cloned in separately. `sanity.php` enforces this and
prints setup instructions if `tsugi/`, `tsugi/config.php`, or the DB tables are missing.

Almost all real functionality (sessions, login, LTI, grades, lessons UI, admin console)
comes from Tsugi. This repo is mostly: top-level page wrappers, site configuration,
course content (book/lectures/code), a few LTI tools, and multi-site theming.

## Running it

Docker is the fastest path (localhost or a Dokploy VPS). See `DOCKER.md` for full detail.

```bash
cp .env.example .env          # set passwords / domain
docker compose up --build     # → http://localhost:8080 ; admin at /tsugi/admin
```

The Docker setup (`Dockerfile`, `docker-entrypoint.sh`, `docker-compose.yml`) clones +
`composer install`s Tsugi at build time, then on boot generates `tsugi/config.php` from
`PY4E_*` env vars, waits for MySQL, and runs the Tsugi DB upgrade. Key facts:

- **`config.php` is generated only if absent.** To pick up changed env vars, recreate the
  container: `docker compose down && docker compose up --build` (add `-v` only to also wipe
  the DB).
- **The DB upgrade must run from inside `tsugi/admin/`** (`cd tsugi/admin && php upgrade.php`)
  — it resolves includes relative to CWD. The clickable "Upgrade Database" button in the
  admin UI is unreliable without an admin session; prefer the CLI.
- **Static assets (bootstrap, jQuery, `tsugi2.css`) are NOT in the tsugi repo.** They are
  served from `$CFG->staticroot`, which defaults to the CDN `https://static.tsugi.org`
  (env `PY4E_STATICROOT`). Pointing staticroot at the local `tsugi` mount 404s the CSS.

Non-Docker (MAMP) setup is documented in `README.md`.

## Tests

**Browser tests** (`tests/`) use Symfony Panther + ChromeDriver and require a running server
and a browser. They are run from the py4e root (never from `tests/`), and `.htaccess` blocks
web access so they only run via CLI. Panther's vendor deps live under `tsugi/`, not `tests/`.

```bash
cd tsugi && vendor/bin/bdi detect drivers   # one-time: install ChromeDriver
php tests/SmokeTest.php                      # single test
php tests/SmokeTest.php --watch              # show the browser window
php tests/run-all.php                        # full suite
php tests/Py4ETests/LessonsTest.php          # one suite
```

Mod tools are not tested directly — they are exercised through the `/tools` store harness
(`/tsugi/store/test`) with built-in test accounts. See `tests/README.md` and `tests/QUICKSTART.md`.

**Python code unit tests** (`./unit.sh`) run `unit3/unit.py`, which validates the example
programs in `code3/`. This is unrelated to the PHP site.

## Architecture

### Front controller & pretty URLs
`tsugi.php` is the front controller. `.htaccess` rewrites any path that isn't a real
file/dir to `tsugi.php`, which (a) uses Tsugi's `FileRouter` to map `/install` → `install.php`,
and (b) mounts Tsugi's LMS controllers (`/lessons`, `/login`, `/announcements`, `/grades`,
`/map`, `/badges`, …) directly under the site root so LMS features appear as part of py4e.

### Page-wrapper pattern
Top-level pages (`index.php`, `materials.php`, `support.php`, `software-*.php`, …) share a
structure: `require top.php` (bootstraps `$CFG`, starts the session, emits `$OUTPUT->header()`),
`require nav.php` (top nav), page body, `require footer.php`. `top.php` and `nav.php`
lazy-load `tsugi/config.php` and start an LTIX session if one isn't running.

### Configuration split
- `tsugi/config.php` — **secret/environment** config (DB creds, `wwwroot`, `apphome`,
  `adminpw`, Google keys). Gitignored; generated by the Docker entrypoint or copied from
  `tsugi/config-dist.php` manually.
- `tsugi_settings.php` — **non-secret** config, `require`d at the end of `config.php`. Sets
  `servicename`, the YouTube playlist, `lessons.json` path, the premium/Stripe extension,
  the vhost extension, and `$CFG->top_menu_callback` → `buildMenu()`.
- `buildmenu.php` — builds the top navigation (`\Tsugi\UI\MenuSet`), branching on login
  state and instructor role.

### Multi-site (vhost variant) system
One codebase serves several sites distinguished by hostname, configured via the `vhost`
extension in `tsugi_settings.php`:

- `www.py4e.com` / `py4e.com` → default site (repo root)
- `ai.py4e.com` → `site-ai/`
- `labs.py4e.com` → `site-labs/`

Each shared page calls `$CFG->requireVhostVariant('top.php')` (etc.). When the active vhost
has an override file (e.g. `site-labs/top.php`, `home.php`, `nav.php`, `buildmenu.php`,
`lessons.json`), it is used instead of the root version, and the root file `return`s early.
`getVhostSiteFile('name')` resolves the correct variant path. When editing a shared page,
check whether `site-ai/` or `site-labs/` has a variant that also needs the change.

### Content vs. tools
- **Course content** lives in `book3/` (Markdown chapters), `lectures3/`, `html3/`, `code3/`,
  `translations/`, `assets/`, `figures/`. `lessons.json` (per-site) drives the Lessons UI.
- **LTI tools** in `tools/` (`pythonauto`, `python-data`, `sql-intro`) are autograders that
  ship with this repo. `mod/` holds Tsugi modules installed via the admin store (gitignored).
  `$CFG->tool_folders` registers `admin`, `../tools`, `../mod`.

## Gotchas

- The install path must contain **no spaces** — `sanity.php` hard-fails otherwise.
- Tsugi's `master` currently requires **PHP ≥ 8.4** (the Docker image is `php:8.4-apache`).
  Pin a specific Tsugi via the `TSUGI_REF` build arg if you need an older PHP.
- `PY4E_APPHOME` / `wwwroot` must match the real public URL — Tsugi builds absolute URLs
  (logins, LTI launches, assets) from them; a mismatch breaks redirects.
